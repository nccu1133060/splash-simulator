## 1. 目的與理由

物質飛濺溯源專題要從一張 A4 紙上的水漬照片，回推液體源頭 (X0, Y0, Z0)。專題的核心創新是
「AI 從斜向水漬形狀估計撞擊速度」，再把速度代入含重力的軌跡回推。

這個 AI 需要大量「每滴速度已知」的水漬影像，但真實實驗很難大量取得，速度標註也要靠高速攝影。
因此本模擬器負責：

1. **主要：產生資料集**，用來訓練「形狀 → 速度」模型（[C] 模組）；附帶的遮罩也能訓練分割模型（[A] 模組）。
2. **次要：驗證回推流程**。源頭是我們設定的已知值，回推結果可以直接和答案比對。

## 2. 目標、非目標、反目標

**目標**
- 產生附完整標準答案的合成 A4 場景圖與單滴切片。
- 水漬形狀和速度的關係必須依據已發表的物理或經驗公式，每條規則都要註明出處。
- 所有「形狀規則」的係數集中在設定檔，日後可以用實拍滴落照片校正，不用改程式。
- 組員能自己調參數、產生資料，並且結果可以重現。

**非目標**
- 流體力學數值模擬（CFD、Blender 流體）。Blender 只保留給專題後期的閉環驗證，不屬本模擬器。
- 用物理方式模擬紙張吸水，改以影像暈染效果近似。
- 圖形介面。
- 透視變形的相機照片。輸出直接是「已拉平的 A4」，跟真實流程第 ① 步之後的狀態一致。
- 回推演算法本身（屬另一個專案階段），但第 5.1 節的飛行物理模組要設計成可以讓回推共用。

**反目標（就算程式能跑也算失敗）**
- AI 只學會「我們隨意編的規則」。形狀規則沒有出處、或無法和實拍照片比對時，就算失敗。
- 相同設定和隨機種子卻產生不同資料（無法重現）。
- 標準答案和圖片不一致（例如答案的撞擊角和畫出來的長寬比對不上）。

## 3. 限制

- 語言：Python（≥ 3.11；開發機為 3.14）。要能在 Windows 與 macOS 上執行，不需要 GPU。
- 使用者：會寫 Python 的組員。
- 座標與單位：以 A4 紙左下角為原點，x 沿短邊（0–210 mm），y 沿長邊（0–297 mm），z 垂直紙面向上。內部一律使用 SI 單位，輸出的位置用 mm。
- 影像規格：2100 × 2970 px，10 px = 1 mm（與真實流程透視校正後一致）。
- 液體：水（預設 ρ = 998 kg/m³、σ = 0.072 N/m、μ = 1.0 mPa·s，可在設定檔調整）。專題決策 8 的「加食用色素」只影響顏色，不影響物性。
- 紙張是水平放置的平面；源頭在紙面上方。

## 5. 系統設計

```
設定檔 (YAML) ──► 參數檢查 ──► 場景取樣器 ──► 飛行模組 ──► 撞擊成形模組 ──► 繪製模組 ──► 影像干擾
                                 (源頭、液滴)    (ODE 積分)     (經驗公式)       (水漬圖案)    (雜訊/模糊)
                                                                                                   │
                         輸出：場景圖、單滴切片、遮罩、標準答案 JSON、設定快照  ◄──────────────────┘
```

每個模組都是獨立的 Python 模組，輸入和輸出是明確的資料結構，可以單獨測試，也可以替換。

### 5.1 飛行模組（真實物理）

- 液滴視為球體，受重力與空氣阻力：m·dv/dt = m·g − ½·ρ_air·C_d·A·|v|·v。
- 阻力係數 C_d 用球體的 Schiller–Naumann 關係式（Re_air < 1000 時 C_d = 24/Re·(1 + 0.15·Re^0.687)，否則 0.44）；設定檔可關閉阻力（只算重力）。
- 數值積分到 z = 0 為止，輸出撞擊點、撞擊速度向量、飛行時間。
- **時間可逆**：同一個函式要能從撞擊狀態往回積分。這是之後回推方法 ②／③ 會直接用到的部分，也是一項驗收測試（往回積分要回到源頭）。
- 液滴在飛行中不會分裂、蒸發，也不會互相碰撞（簡化假設，寫在輸出的 metadata 裡）。

### 5.2 場景取樣器

場景模式（設定檔可選）：

1. **噴射場景（預設）**：一個點源，在一個錐角內隨機發射 N 滴，速度與液滴直徑依設定的分布隨機取樣。只保留落在 A4 範圍內的液滴；落在紙上的滴數低於下限（預設 9 滴，依 Joris 2015）時重新取樣。
2. **垂直滴落場景**：從已知高度、固定直徑垂直滴下（對應滴管實拍校正實驗）。每張圖一滴，或是排成格狀的多滴。用來和實拍照片一對一比對。
3. **單滴模式**：直接指定撞擊速度向量與直徑，跳過飛行段。用來快速產生速度模型的訓練切片，以及做單元測試。

預設參數範圍參考專題實驗設計（Claude 判斷，可在設定檔修改）：
- 源頭高度 Z0：10–30 cm 均勻分布。
- 源頭水平位置：紙張中心 ±30 cm 內均勻分布，可以在紙外（真實噴濺的源頭通常不在紙的正上方）。
- 發射方向：以朝向紙張中心為軸、半角 30° 的錐內隨機。
- 發射速度：0.5–5 m/s 均勻分布。
- 液滴直徑：固定 3.0 mm（對應決策 6 的方案 A，模擬滴管）；可以改成 0.3–4 mm 的對數均勻分布。
- 每場景發射 30–80 滴，落在紙上至少 9 滴。

### 5.3 撞擊成形模組（經驗公式，參數可校正）

由撞擊速度向量 v、液滴直徑 d、液體物性，計算水漬的幾何描述：

| 量 | 預設規則 | 出處（寫入報告前需核對原文） |
|---|---|---|
| 無因次數 | We = ρ·v_n²·d/σ、Re = ρ·v_n·d/μ，v_n 為法向分量 | 標準定義 |
| 最大攤開係數 ξ = D_max/d | Laan 2014 的內插式 ξ·Re^(−1/5) = √P / (A + √P)，P = We·Re^(−2/5)，A ≈ 1.24 | Laan et al., Phys. Rev. Applied 2014 |
| 寬度 W | W = ξ·d | 同上 |
| 長度 L | L = W / sin α（α 為撞擊角）；另有可選的系統偏差項 | 經典 W/L 關係；Joris 2017 指出偏差 |
| 方向 γ | 撞擊速度在紙面的投影方向 | 幾何 |
| 毛刺數 N_s | N_s = a·We^b，係數 a、b 由設定檔提供 | Hulse-Smith 2005、Mehdizadeh 2004（係數待核對） |
| 毛刺分布 | 斜撞時集中在前緣，集中程度隨 cos α 增加 | 專題統整第十一節；係數可調 |
| 尾巴長度 | 隨切向速度與 α 增加，係數可調 | 定性關係，標記為「待實拍校正」 |
| 衛星小滴 | 超過 We 門檻才出現，數量與距離可調 | 定性關係，標記為「待實拍校正」 |
| 暈染 | 依紙種（塗佈紙／影印紙）的邊緣擴散寬度 | 待實拍校正 |

規則：
- 每條規則在程式和設定檔中都要註明出處，以及「已有文獻」或「待實拍校正」的狀態。
- 形狀規則以可替換的「規則組」實作，組員可以換成自己的版本做實驗，而不必改動其他模組。
- 模組產出的是**幾何描述**（橢圓參數、毛刺列表、衛星點列表、尾巴參數），不是像素。繪製由下一個模組負責，這樣標準答案能直接取自幾何描述。

### 5.4 繪製模組與影像干擾

- 依幾何描述，把每滴水漬以向量方式畫到 A4 畫布上（OpenCV／NumPy，抗鋸齒）。
- 同時輸出**實例遮罩**：每滴水漬一個編號，衛星小滴歸屬於母滴、另外標記。
- 影像干擾（各自可開關，強度可調）：紙張紋理、光線不均、色素濃淡、高斯模糊、感光雜訊、JPEG 壓縮。干擾只施加在場景圖上，不施加在遮罩與答案上。
- 單滴切片：以每滴中心裁出固定大小的方塊（預設 384 × 384 px，即 38.4 mm）。**切片不縮放**，維持 10 px = 1 mm，因為水漬的實際大小本身就是速度線索。切片也不旋轉（是否旋轉對齊留給訓練端決定）。水漬超出切片範圍時，在答案中標記 `truncated: true`。

### 5.5 輸出格式

每次執行產生一個資料集資料夾：

```
datasets/<名稱>_<時間>/
  config_snapshot.yaml        當次完整設定（含隨機種子、程式版本）
  scenes/scene_00001.png      場景圖
  masks/scene_00001.png       實例遮罩（16-bit，0 = 背景）
  crops/scene_00001_d003.png  單滴切片
  labels/scene_00001.json     標準答案
  index.csv                   每滴一列的扁平表（給 XGBoost 等表格模型直接讀）
```

`labels/*.json` 內容：源頭座標與發射參數；每滴的撞擊點 (mm)、撞擊速度向量與大小 (m/s)、撞擊角 α、方向角 γ、直徑 d、We、Re、W、L、毛刺數、是否有尾巴與衛星小滴、外框、切片檔名；以及使用的規則組名稱與版本。

另外提供 YOLOv8-seg 標註格式的轉換指令（多邊形 txt），供分割模型訓練使用。

### 5.6 介面

- 指令：`uv run splash-sim generate --config configs/default.yaml --out datasets/`、`splash-sim preview --config …`（產生 1 張並開啟，用來調參數）、`splash-sim export-yolo …`。
- Python：`from splash_sim import simulate_scene, simulate_single_drop, load_config`。
- 設定檔：YAML 格式，每個欄位都有中文註解。附一份預設設定 `default.yaml`，以及「垂直滴落校正」「固定液滴大小」兩份範例設定。
- 設定檢查：欄位名稱、型別、範圍有錯時，用中文指出是哪一欄、錯在哪裡、合理範圍是多少。

### 5.7 可重現性

- 同一份設定（含隨機種子）在同一個程式版本下，產生的資料逐位元組相同。
- 每張場景用「主種子＋場景編號」衍生出自己的種子，所以只重產第 N 張的結果也會一樣。

### 5.8 模擬與實拍比對工具（第二里程碑）

- 特徵擷取：對任一張單滴影像（模擬或實拍）量測面積、長寬比、毛刺數、邊緣粗糙度。
- 比對報告：把同條件下模擬與實拍的特徵分布並排列出，用來校正 5.3 的係數。
- 這是讓「像不像真的」變成數字的關鍵。第一里程碑先把特徵擷取函式做出來並用在測試中；比對報告等有實拍資料時再完成。

## 6. 驗收標準

1. **飛行**：關閉阻力時，數值解和拋體解析解的落點誤差 < 0.01 mm；從撞擊狀態往回積分，回到源頭的誤差 < 0.01 mm。
2. **一致性**：對繪製出的每滴水漬用 `cv2.fitEllipse` 量測，量到的 W/L 和答案 sin α 的差距在設定的容許值內（未開偏差項時）；量到的方向角和答案 γ 相差 < 2°（忽略 180° 模糊後）。
3. **物理單調性**：其他條件固定時，速度越高，攤開直徑和毛刺數不會減少。
4. **可重現**：同一份設定執行兩次，輸出檔案的雜湊值相同。
5. **設定檢查**：故意填錯（負高度、未知欄位）時，出現中文錯誤訊息並指出欄位名稱。
6. **效能**：在一般筆電上，一張場景圖（含 20 滴與切片）的產生時間 < 2 秒。
7. **組員可用**：依 README，在乾淨的 Windows 環境從安裝到產生 10 張預覽圖不超過 3 個指令。

## 7. 交給實作者決定的事

- 內部模組與檔案切分、資料結構細節。
- 毛刺、尾巴、衛星小滴的具體繪製方式（只要符合 5.3 的幾何描述，並通過第 6 節的驗收）。
- 紙張紋理與干擾的具體演算法。
- 測試框架（預設 pytest）與套件管理（預設 uv，README 附 pip 替代方式）。

## 8. 已知風險

| 風險 | 應對 |
|---|---|
| 經驗公式多來自血液或不吸水表面 | 規則參數化，用水＋紙的實拍照片校正（5.8） |
| 毛刺係數的文獻值尚未核對 | 設定檔標示「待核對」，報告前逐篇核對 |
| 程式畫出的毛刺太規則，AI 學到繪製方式而非物理 | 加入隨機擾動；最終以實拍測試集評估；模擬與實拍成績分開報告 |
| 暈染只是影像效果 | 列為已知限制，以實拍校正暈染寬度 |
